# 沙箱

Foya 的 `bash`、`write`、`edit` 工具统一通过 `sandbox.Runner` 执行。沙箱只负责操作系统级约束；工具可见性和审批决策仍由 Agent 工具白名单与 `approval.Gateway` 处理。

## 权限模型

- `manual`（手动审批）启用平台沙箱。本地读取自动放行，写入、执行和联网操作等待用户确认。
- `auto`（自动审批）启用平台沙箱。本地读取自动放行，写入、执行和联网操作由当前 Session 的模型作为 Guardian 判断。
- `full_access`（完全访问）关闭沙箱和审批，命令直接使用宿主机权限。
- 受限模式默认允许读取文件和启动子进程，默认禁止网络。
- 项目目录、系统临时目录和用户缓存目录可写。
- 项目内已存在的 `.git`、`.agents`、`.foya` 以只读方式覆盖。
- 沙箱后端或必要依赖不可用时失败关闭，不会退化为宿主机直接执行。

`write` 和 `edit` 可以在内核中读取文件及计算 diff，但实际文件修改由执行边界内的文件写入子进程完成。

Guardian 使用当前 Session 的 Provider、Model 和推理强度，不提供任何工具。模型调用失败、Provider 不支持非流式补全或返回值不符合严格 JSON 格式时，操作会被拒绝。Guardian 的单次批准不会写入授权缓存。

手动审批可以选择“仅本次允许”或“本 Session 内允许”。Session 授权按会话、工具、动作和资源范围缓存；项目内文件操作以工作区为范围，命令以工作目录为范围，`web_search` 和 `web_fetch` 以 Internet 为范围，MCP 工具以 MCP Server 为范围。删除 Session 时会清除其授权缓存。

旧的 `explore`、`ask`、`bypass` 模式不再接受。

## macOS

使用系统自带的 `/usr/bin/sandbox-exec`（Seatbelt）。通过动态生成的 profile 限制文件写入和网络访问，并阻止通过符号链接写出可写根目录。

## Linux

使用固定路径 `/usr/bin/bwrap`（Bubblewrap），要求宿主机已安装 Bubblewrap，并允许其创建必要的 namespace。

Bubblewrap 使用只读根文件系统，并为允许写入的目录叠加读写 bind mount。已存在的受保护目录随后叠加只读 bind mount。禁网模式创建独立 network namespace，并使用私有 `/run` 隔离宿主机运行时 socket。

Debian/Ubuntu：

```bash
sudo apt install bubblewrap
```

Fedora：

```bash
sudo dnf install bubblewrap
```

## Windows

受限模式通过 `%SystemRoot%\System32\wsl.exe` 进入默认 WSL2 发行版，再使用 `/usr/bin/bwrap` 执行与 Linux 相同的策略。

前提：

1. 已安装并启用 WSL2。
2. 默认 WSL 发行版内存在 `/usr/bin/bwrap`。
3. 项目所在 Windows 路径能通过 `wslpath` 映射并在 WSL 中访问。

受限 `bash` 使用 WSL 内的 `/bin/sh`，因此命令应使用 POSIX shell 语法，并优先使用相对项目目录的路径。`write` 和 `edit` 的 Windows 路径由执行边界显式转换。

为防止从 WSL 回到宿主机进程而绕过 namespace，沙箱内会移除 `WSL_INTEROP` 和 `WSLENV`、隐藏 `/run` 下的互操作 socket，并遮蔽 WSL 的 `/init`。完整访问模式不会进入 WSL，仍使用原生 `cmd.exe` 和 PowerShell。

Windows 后端会忽略不存在的只读覆盖路径；因此 `.git`、`.agents`、`.foya` 在执行开始前已经存在时才会被只读挂载。
